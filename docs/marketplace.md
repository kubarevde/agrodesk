# Маркетплейс АгроДеск (MVP)

Кратко: публичная витрина экопродукции (`/market`) + кабинет продавца внутри org (`/seller-market`) + модерация у суперадмина.  
Модель — **доска объявлений**: покупатель оставляет заявку с телефоном, продавец связывается вне системы.  
Модуль **выключен по умолчанию** и **не** смешивается с учётом КФХ (отчёты, KPI, смены, финансы).

**Статус: Реализовано (MVP, 2026)** — с осознанными ограничениями ниже.  
Код: промпты 2.1–2.14. Границы с КФХ — § «Изоляция от основного продукта».

---

## Назначение

| Аудитория | Что делает |
|-----------|------------|
| Покупатель (аноним) | Каталог, поиск/фильтр, карточка товара, заявка |
| Сотрудник org с `marketplace.manage` | Профиль магазина, объявления, импорт со склада/отгрузок, заявки |
| Суперадмин | Включение витрины для org, категории, модерация, продавцы, заказы |

Одна VPS: Postgres + API + frontend + uploads volume. Отдельного сервиса оплаты/CDN нет.

## Как работает модуль (подробно)

### 1. Включение

1. В `organizations.settings` ключ `marketplace_enabled` (по умолчанию **false** / отсутствует).
2. Включает **суперадмин**: `PATCH /superadmin/api/organizations/{id}` с `{ "marketplace_enabled": true }`.
3. Орг-админ в `/api/settings/organization` видит флаг **только для чтения** — включить сам не может.
4. При `false` из effective actions вырезается `marketplace.manage`; пункт «Магазин» скрыт.

### 2. Права

| Действие | Условие |
|----------|---------|
| Видеть «Магазин» в меню | `marketplace_enabled` **и** `marketplace.manage` |
| API `/api/marketplace/*` | JWT org + `marketplace.manage` (+ флаг) |
| Admin org | Все actions, включая `marketplace.manage` (если флаг on) |
| Employee / manager по умолчанию | **Нет** `marketplace.manage` — только access group |

### 3. Жизненный цикл объявления

```
draft → pending_review → published
                      ↘ rejected → (правки) → pending_review → …
любой (кроме archived) → archived
```

1. Продавец создаёт вручную или импортирует snapshot → **draft**.
2. Для модерации нужны: название, категория, цена > 0, количество > 0, ≥1 фото.
3. `POST .../listings/{id}/submit` → **pending_review**.
4. Суперадмин **Одобрить** → **published** (витрина) или **Отклонить** + причина → **rejected**.
5. Повторная публикация только через submit + модерацию (самопубликации нет).

### 4. Публичная витрина

URL: `/market`, `/market/product/$id`, `/market/seller/$id`.  
API: `/api/public/marketplace/*` (middleware org JWT **не** требуется).

На витрине только если одновременно:

- `market_listings.status = published`
- `organizations.is_active`
- `settings.marketplace_enabled = true`
- `market_seller_profiles.is_active`

Soft-delete org (`is_active=false`) **скрывает** листинги без «осиротевших» карточек.

Покупатель: поиск, категории, сортировка → форма заявки → успех.  
Оплата в системе **не** происходит.

### 5. Заявки (orders)

Статусы продавца: `new` → `contacted` → `confirmed` → `completed` (или `cancelled`).  
При создании заявки: inbox сотрудникам с `marketplace.manage`, опционально Telegram.  
Покупателю push/SMS о смене статуса **нет**.

### 6. Импорт со склада / отгрузок

`GET /api/marketplace/import-sources` → `POST /api/marketplace/listings/from-source`.

- Копируются название, единица, количество **на момент импорта**.
- `category_id` — если есть mapping кода склада → категории витрины; иначе `null`.
- Повторный импорт того же активного источника → **409**.
- Строки `inventory_items` / `shipments` **не** изменяются.
- Дальше остаток склада и `quantity_available` листинга **живут отдельно** (не live sync).

### 7. Медиа

- Upload: `/api/uploads/image`, `folder=marketplace` (существующий Pillow-ресайз).
- До **8** фото на листинг; лого продавца — 1 файл.
- Nginx: длинный `Cache-Control` только для `/uploads/marketplace/` (не трогая `/sw.js`, `/index.html`).

### 8. Код и API (карта)

| Слой | Путь |
|------|------|
| Public FE | `src/features/marketplace-public/` |
| Seller FE | `src/features/seller-market/` |
| Superadmin FE | `src/features/superadmin/components/Marketplace*` |
| Public API | `/api/public/marketplace/listings`, `.../orders`, `.../categories`, `.../sellers/{id}` |
| Seller API | `/api/marketplace/seller-profile`, `/listings`, `/orders`, `/import-sources`, `/listings/from-source` |
| Superadmin API | `/superadmin/api/marketplace/*` |
| E2E | `e2e/marketplace.spec.ts`, `e2e/marketplace-helpers.ts` |

## Осознанные ограничения MVP

1. **Нет эквайринга / онлайн-оплаты** — только заявка на связь (доска объявлений). Деньги и договорённости вне АгроДеск.
2. **Остатки склада не синхронизируются в реальном времени** с опубликованными листингами. Импорт и ручное редактирование — **snapshot**; списание склада при заказе с витрины **не** делается.
3. **Нет развитой системы рейтинга** — показ отзывов и простое среднее на UI; без взвешенного рейтинга, без обязательной привязки «отзыв только после подтверждённой покупки», без публичного API создания отзыва в MVP.
4. **Нет мобильного приложения** — только адаптивная веб-витрина (PWA/браузер).
5. **Склад / отгрузки** — источник для **быстрого импорта**, не «живая» двусторонняя интеграция и не единый остаток с витриной.
6. **Отчёты и KPI КФХ** не включают `market_orders` / выручку витрины.
7. **Покупатель** не получает уведомлений об изменении статуса заявки.

## Изоляция от основного продукта

### Использует от КФХ

| Ресурс | Как |
|--------|-----|
| Auth / JWT сотрудников | Кабинет `/seller-market`, `/api/marketplace/*` |
| Organization | `marketplace_enabled`, `is_active` |
| Employees + access groups | `marketplace.manage` |
| Inventory / shipments | Только read-snapshot при импорте |
| Uploads | Тот же image endpoint |
| Notifications | Тип `new_market_order` (VARCHAR) |

### Не пересекается

| Контур | Почему |
|--------|--------|
| `/api/reports/*`, `/api/dashboard` | Нет импорта marketplace-моделей |
| Смены / зарплата / затраты | Нет FK на `market_*` |
| Роли по умолчанию | `marketplace.manage` не в `MANAGER_EXTRA_ACTIONS` / section implied |
| FE features | Нет импортов `marketplace*` ↔ `dashboard` / `inventory` / `worktime` / `reports` |

Объединение продаж витрины с финансами КФХ — только отдельная осознанная фича.

## Что дальше (фаза 2 — не в текущем MVP)

Кандидаты (не реализовывать «заодно»):

1. **Онлайн-оплата с холдом** до подтверждения получения (эскроу / безопасная сделка) + чеки/возвраты.
2. **Живая синхронизация остатков** (listing.qty ↔ склад или явный резерв при заявке).
3. **Рейтинг с подтверждённой покупкой** (отзыв только после `completed` + публичный POST / moderation).
4. **Push / SMS / email покупателю** при смене статуса заказа (opt-in, согласие на контакт).
5. Отдельный отчёт «продажи витрины» (явный, не подмешивание в Excel КФХ).
6. SLA модерации, шаблоны отказов, bulk-approve.
7. Геофильтр витрины / регионы доставки (сейчас — единый каталог).

## E2E и известная нестабильность смен

**Маркетплейс:** `e2e/marketplace.spec.ts` — disposable org через SuperAdmin, cleanup `E2E-MKT-*` + soft-delete; Demo AgroDesk не трогает.  
При последнем успешном прогоне все тесты marketplace — **зелёные**.

**Совместный прогон с `e2e/shifts.spec.ts`:** marketplace не ломает смены. Падение первого теста смен («открытие и закрытие смены онлайн») воспроизводится **и в одиночку**.

### В чём проблема смены (не маркетплейс)

1. Хелпер `openShift` в `e2e/helpers.ts` открывает диалог «Открыть смену за сотрудника», выбирает EMP001 («Иванов»), жмёт «Начать смену» и ждёт, что диалог **скроется**.
2. Диалог **остаётся открытым** 15+ с → assert `toBeHidden` падает.
3. Типичная причина такого UX: **API create shift не успешен** (часто **409** — у EMP001 уже есть открытая смена), форма показывает ошибку/toast, модалку не закрывает.
4. `closeAllOpenShifts` перед открытием должен чистить «Открытые», но фильтр завязан на `getByRole('combobox').nth(1)` — хрупко; часть открытых смен EMP001 может **не** закрыться → 409 при «Начать смену».
5. Это **существующая нестабильность e2e смен / хелпера**, не побочный эффект маркетплейса и не регрессия от промптов 2.1–2.14.

Исправление смен — отдельная задача (надёжный cleanup открытых смен по employee / API, assert на toast ошибки, а не только на скрытие диалога).
