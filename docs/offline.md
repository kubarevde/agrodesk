# Офлайн-режим АгроДеск

Кратко: приложение открывается без сети **после** первого онлайн-визита и установки.  
Офлайн-запись: **смены** (открытие/закрытие) и **операции склада** (приход / расход / корректировка).  
Остальные модули — online-only или просмотр из кэша после прогрева.

> **Прод:** офлайн проверять только на установленном PWA / `npm run preview` / VPS.  
> `npm run dev` **без** service worker — сценарий офлайна там невалиден.

---

## Критичный блокер: закрытие смены ONLINE

До исправления `POST /api/shifts/{id}/close` мог отдавать **500**, особенно для техники с `meter_type = shift_hours`.

**Первопричина:** после `add_equipment_meter_log` → `flush` SQLAlchemy expire'ил атрибуты смены; `model_snapshot()` делал `getattr` → lazy-load под AsyncSession → `MissingGreenlet` → 500.

**Исправление:** async-safe `model_snapshot` (только `state.dict`) + снимок `after` до meter-flush + meter-ошибка не блокирует close.

Без этого offline→sync для close тоже «висела» (очередь получала 500).

## Для пользователя

### Подготовка (обязательно онлайн)
1. Откройте сайт **с интернетом** и войдите.
2. Дождитесь индикатора **«Онлайн»** в шапке.
3. Нажмите **«Установить приложение»** (Android Chrome) или Safari → **«На экран Домой»**.
4. Один раз откройте приложение **из иконки** ещё онлайн — так закрепляется service worker.

Готовность: в шапке «Онлайн», меню открывается, раздел «Рабочее время» загружается.

### Работа без интернета
1. Запускайте **из иконки**, не из сохранённой вкладки браузера.
2. В шапке — **«Офлайн»** и баннер.
3. В **«Моя смена»** / **«Рабочее время»** — смены; в **«Склад»** — приход/расход/корректировка → «сохранено офлайн».
4. Жёлтое число в шапке = очередь синхронизации. На складе конфликты остатка помечаются «Проверка» + кнопка «Повторить».

> **Важно:** одного «добавить на экран» недостаточно. Нужен **предварительный online-визит** в «Моя смена» / «Рабочее время», чтобы Service Worker и справочники (объекты, типы работ, поля, техника) попали в кэш. Без этого форма открытия смены офлайн будет пустой.

### После появления сети
1. Откройте приложение (или дождитесь «Онлайн»).
2. Очередь уходит сама.
3. Если остались ошибки (красный счётчик) — нажмите **обновление (Повторить)** в шапке.
4. Убедитесь, что счётчик исчез.

### Вкладка ≠ PWA

| Способ | Офлайн |
|--------|--------|
| Сохранённая вкладка | Часто **не** открывается / нестабильно |
| «На главный экран» / Установить | Shell из кэша после прогрева — **рекомендуется** |
| `npm run dev` | **SW нет** — офлайн-сценарий не тестировать так |

### Если очередь зависла
1. Включите интернет.
2. Нажмите «Повторить» в шапке.
3. Перезапустите приложение из иконки.
4. Если не помогло — обратитесь к администратору (не удаляйте данные вручную).

### Если офлайн «Начать смену» не работает
1. Убедитесь, что открыто **установленное** приложение (без адресной строки), не вкладка.
2. Сборка — **prod** (`preview` / VPS), не Vite dev.
3. Один раз зайдите **онлайн** в «Моя смена» (списки объектов/типов работ подтянутся в IndexedDB).
4. Выключите сеть → снова из иконки → «Начать смену» → toast «Сохранено офлайн»; в DevTools → Application → IndexedDB → `agrodesk` → `syncQueue` должна появиться запись.

## Границы offline support

| Модуль | Read офлайн | Write офлайн | Примечание |
|--------|-------------|--------------|------------|
| App shell / меню | Да* | — | *после онлайн-визита + SW |
| Auth bootstrap | Да* | — | кэш профиля; 401 сбрасывает сессию |
| Смены | Да* | **Да** | Dexie `syncQueue`; RQ `networkMode: always` на create/close |
| Склад (операции) | Да* | **Да** | Dexie `inventoryQueue` + optimistic RQ; conflict при расхождении остатка |
| Справочники (объекты, типы работ…) | Да* | Нет | греются с «Моя смена» / форма открытия |
| Техника / поля | Частично* | Нет | локальный кэш при наличии |
| Создание позиций ТМЦ | Нет | Нет | online only |
| Затраты / отгрузки | Нет / UI-заглушка | Нет | online only |
| Дашборд | Нет / last stats | Нет | online only |
| Отчёты | Нет | Нет | online only |
| Финансы KPI | Нет | Нет | через dashboard API |

\* Зависит от предварительного кэширования при работе онлайн.

### Техническая причина бага (июль 2026)

TanStack Query по умолчанию использует `networkMode: 'online'`: офлайн **мутации** (открытие/закрытие смены) ставились на паузу и **не вызывали** запись в `syncQueue`, даже при установленном PWA. Исправлено: `networkMode: 'always'` на create/close и `offlineFirst` на чтение смен/справочников; техника пишется в Dexie из reference-хуков; «Моя смена» прогревает справочники онлайн.

## Для разработки

### Как тестировать
```bash
npm run build && npm run preview
# DevTools → Application → Service Workers (должен быть activated)
# Network → Offline → reload (сессия не должна уходить на /login)
# Application → IndexedDB → agrodesk → locations / workTypes / syncQueue
npm test -- src/features/auth/authOffline.test.ts
npm run test:e2e -- e2e/shifts.spec.ts
cd backend && python -m pytest tests/test_close_shift_online.py -q
```

### Важно
- Service worker **только в production** (`build` / `preview` / деплой), не в `npm run dev`.
- Auth: `agrodesk_user_cache` + токен; офлайн не вызывает `/api/auth/me`.
- `flushSyncQueue` — mutex (startup + online + retry не гоняются параллельно).
- Retry вручную: `includeFailed: true` переводит failed → pending.
- Nginx на VPS: отдельные `location` для `index.html`, `sw.js`, `manifest.webmanifest` с `Cache-Control: no-cache` (см. `nginx/agrodesk*.conf`).

### Типовые поломки после деплоя
1. `sw.js` / `index.html` с долгим cache → старый shell / вечный старый SW.
2. `VITE_BASE_PATH` без relative manifest → сломан install/start_url.
3. Auth снова дергает `/me` без fallback → logout офлайн.
4. Ожидание offline write вне **смен и склада** — не реализовано (затраты, отгрузки, планы и т.д.).
5. Backend API без рестарта после фикса close → offline close queue снова получает 500.
6. Склад офлайн без предварительного онлайн-открытия раздела → нет кэша позиций / optimistic UI пустой.

### Manual QA checklist (релиз)
- [ ] Онлайн: логин, «Онлайн», SW installed/activated (prod).
- [ ] Установка PWA / Add to Home Screen.
- [ ] Открыть из иконки онлайн.
- [ ] Выключить сеть → открыть из иконки → **не** `/login`.
- [ ] Баннер офлайн виден.
- [ ] Открыть смену офлайн → очередь +1 → reload → запись на месте.
- [ ] Закрыть смену офлайн → очередь.
- [ ] Включить сеть → очередь очищается / Retry работает.
- [ ] Закрытие смены **онлайн** с техникой `shift_hours` → 200, не 500.
- [ ] На складе: приход/расход офлайн → очередь / optimistic; после сети — flush; конфликт остатка → «Проверка» + «Повторить».
- [ ] Дашборд/Отчёты офлайн показывают честный online-only notice.
- [ ] Android Chrome + (по возможности) iOS Safari.
